# Case: freekery worker — 2026-10-20 (read-only, static)

## Zakres i metoda
- Projekt: `<workspace>/products/freekery`.
- Pliki: `docker-compose.yml`, `Dockerfile`, `cmd/freekery-host/main.go`,
  `config/agents.json`, `bin/freekery-bootstrap`, `.dockerignore`,
  `docs/ARCHITECTURE.md`, `docs/RUNBOOK.md`, mount `${AIGON_ROOT:-<workspace>}`.
- Stack **nieuruchomiony**: `ss -ltnp` nie widział `39100` ani `6379`.
  Wniosek: ocena konfiguracji, nie potwierdzony live weakness.
- Bez `docker`, bez `curl`, bez nmap. Tylko `rg`, `stat`, `ss`.

## Findings (top 5)

### 1. KRYTYCZNE — `POST /run` bez auth
- `cmd/freekery-host/main.go:405-419` — `mux.HandleFunc("/run", ...)`,
  `json.NewDecoder(r.Body).Decode(&t)`, `runTask(...)`.
- `main.go:411` — brak `http.MaxBytesReader` (body bez limitu).
- `main.go:418` — wynik agenta wraca w response.
- `config/agents.json:5,10` — `--yolo`, `--dangerously-skip-permissions`.
- `docker-compose.yml:39-40` — port `39100` publikowany domyślnie na 0.0.0.0.
- `main.go:272-279` — `timeout_s` z requestu bez górnego limitu.
- `main.go:421` — `http.ListenAndServe` bez `ReadHeaderTimeout`/`ReadTimeout`/
  `WriteTimeout`.
- Skutek: dowolny `agent`/`prompt`/`repo` → RCE w kontenerze i kanał
  exfiltracji; agent dziedziczy env workera.

### 2. KRYTYCZNE — mount `<workspace>` + światowo czytelne sekrety
- `docker-compose.yml:19`:
  `${AIGON_ROOT:-<workspace>}:/aigon:ro`.
- Kontener: `user: "1001:1001"` (`docker-compose.yml:11`); to primary GID
  1001, nie hostowa grupa `aigon`.
- `stat -c '%a %U:%G %n'` na hostcie:

| ścieżka | tryb | właściciel | czytelne dla UID 1001 |
|---|---|---|---|
| `<workspace>/core/.env` | 640 | aigon:aigon | NIE |
| `<workspace>/config/secrets/agent-mcp.token` | 640 | aigon:aigon | NIE |
| `<workspace>/infra/vault/vault-init.json` | 640 | aigon:aigon | NIE |
| `<workspace>/.env` | 664 | aigon:aigon | **TAK** |
| `<workspace>/runtime/.secrets/runtime-master.env` | 664 | aigon:aigon | **TAK** |
| `<workspace>/voice/.env` | 644 | aigon:aigon | **TAK** |

- Katalogi `config/secrets`, `core`, `infra/vault`, `runtime/.secrets` mają
  `2775` — UID 1001 listuje nazwy, ale pliki `640` czyta tylko owner/gid.
- `<workspace>/.env` ma 271 linii; `runtime-master.env` 3 wpisy sekretne.
  Wartości NIE były cytowane.
- Wniosek: `:ro` nie chroni przed odczytem; `640` jest OK, `664/644` nie.

### 3. WYSOKIE — agent dziedziczy pełne env workera
- `main.go:452-456` — `os.Environ()` w `buildEnv`.
- `docker-compose.yml:27-28` — dwa sekrety platformy w env workera.
- `config/agents.json:12-15` — env agenta rozwijany z env workera.
- Skutek: task może wykonać `env`/`printenv` i odesłać JWT platformy oraz
  router key; nie trzeba czytać plików.

### 4. WYSOKIE — Redis 6379 bez hasła/ACL
- `docker-compose.yml:56` — `redis-server` bez `requirepass`/`ACLfile`.
- `docker-compose.yml:60` — `"6379:6379"` publikowane na host.
- `docker-compose.yml:23` — `redis://redis:6379/3` bez TLS.
- `docs/RUNBOOK.md:18` — wspomina hasło Redis, ale compose go nie ustawia.
- `protected-mode` nie jest ACL; może blokować część połączeń, ale nie
  zastępuje auth. Kolejka `freekery:tasks` → ten sam `runTask` = RCE.

### 5. WYSOKIE — brak egress policy i limitów HTTP
- `docker-compose.yml:31-33` — tylko `extra_hosts`, brak `networks`/polityki.
- Domyślny bridge + NAT: worker może wyjść gdziekolwiek.
- `main.go:421` — brak timeoutów serwera HTTP.
- `main.go:411` — brak limitu body.
- `main.go:272-279` — brak maks. `timeout_s`.
- Skutek: exfiltracja, SSRF przez `repo`/`git clone`, Slowloris, zalanie
  agentami (DoS).
